# Trabox / WebKit 項目正規化仕様書 ver1.1

**最終更新: 2026-08-04**

## 0. 改版ルール（重要）
- この仕様書は Carroo の荷物登録フォームが持つ「共通語彙（正規化フィールド）」と、Trabox・WebKit 双方への変換ルールを定義する。
- フォーム項目・マッピングルールを追加/変更したら、必ずこの仕様書も改版する。
- 上書きせず、`Trabox_WebKit項目正規化仕様書_ver1.2.md` のようにバージョンを上げた新ファイルを作り履歴を残す（`docs/` 仕様書の共通ルールに準拠）。
- 実装は `app/automations/trabox_form_mapper.py`（Trabox変換）・`app/constants/webkit_codes.py`（WebKit変換）・`app/routers/cases.py`（フォーム定義）に反映し、常にこの仕様書と一致させる。

## 1. 背景・目的
Trabox と WebKit は、同じ概念（車種形状・荷物区分など）を**別々のコード体系**で持っている。これまで場当たり的に変換していたため、
- 重量クラス（8t以上）が仮想スクロールの都合で選択できず「問わず」に落ちる
- 車種形状の付帯（低床・パワーゲート・エアサス）が WebKit 側で握りつぶされる
- 荷物区分が自由入力のため WebKit 側の固定コード表と一致せず「その他」に丸められる

といった不具合が連続して発生した（2026-08-03〜04 に発覚・修正）。**Carroo が持つ1つの正規化された入力**から、Trabox・WebKit それぞれの表現に変換する設計に統一する。

### D. 温度帯（横断的な概念・重要）

ユーザー指摘（2026-08-04）: 冷凍・冷蔵・チルド等の「温度帯」は、**複数の項目にまたがって表現される**概念であり、1箇所に押し込めると情報が欠落する。

| 表現手段 | Trabox | WebKit |
|---|---|---|
| 車種形状（#1）で表現 | 「冷凍」「保冷」の2択のみ（車種そのものを冷凍車/保冷車に絞る） | 同上（`carkindtype`にも冷凍/保冷相当のコードあり） |
| 荷物区分（#9）の自由記述/固定コードで表現 | 自由記述欄に「食品(チルド)」「食品(冷蔵)」等と書ける | 21択の固定コードには「食料品」「飲料品」しかなく、チルド/冷蔵の粒度は表現できない |
| 輸送取扱区分（#10）で表現 | 概念なし | 「保冷」「冷凍」「常温」「冷蔵」の4段階で明示できる（新規追加項目） |

**方針**: 温度帯そのものを独立の正規化フィールドとして新設するのではなく、**既存の#1（車種形状）と#10（輸送取扱区分）の両方を、ユーザーが必要に応じて個別に選択する**運用とする。自動連動（例: 車種形状で「冷凍」を選んだら輸送取扱区分の「冷凍」も自動チェック）は行わない（過剰な自動化はかえって誤登録のリスクがあるため）。Trabox側で温度帯のニュアンスを伝えたい場合は、荷物区分の自由記述（#9のTrabox転記）に手動で書き添えることを運用でカバーする。
