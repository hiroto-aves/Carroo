# Carroo エラー体系仕様書 ver1.2

**最終更新: 2026-08-04 / 対象リビジョン: carroo-00107 系**

## 0. 改版ルール（重要）
- **`app/errors.py`（ERROR_CATALOG / classify / AppError / NON_RETRYABLE_CODES / FIELD_LABELS）や共通ハンドラ（`app/main.py`）、投稿失敗の分類適用（`app/services/poster.py`）、リトライ制御（`app/routers/tasks.py`）を変更したら、必ずこの仕様書も改版する。**
- 上書きせず、`エラー体系仕様書_ver1.3.md` のようにバージョンを上げた新ファイルを作り履歴を残す（`docs/` 仕様書の共通ルールに準拠）。
- 変更時は下部「改版履歴」に1行追記する。

## 1. 目的・方針
- **エンドユーザー**にはやさしい日本語の説明を出す。
- **管理者**が原因調査できるよう、**エラーコード**（＋500系は**参照ID**）を必ず併記する。
- コードは `detail` 文字列に埋め込むため、既存のフロント表示（`result.detail`）がそのまま対応できる。
- 表示形式: `{やさしい説明}（コード: {CODE}[ / 参照: {REF}]）`
  - 例: `投稿サイトの反応が遅く…（コード: E-POST-TIMEOUT / 参照: a1b2c3d4）`

## 2. 実装の場所
| 役割 | ファイル |
|---|---|
| コード表・分類・整形・業務例外・リトライ不能集合・フィールド名対応表 | `app/errors.py` |
| 共通例外ハンドラ（AppError / 422 / 未捕捉500 / 401リダイレクト） | `app/main.py` |
| 投稿失敗の分類適用（DBの error_message・結果メール） | `app/services/poster.py` の `_friendly()` |
| 全プラットフォーム失敗時のリトライ/DLQ制御 | `app/routers/tasks.py` |
| ログイン失敗の文言 | `app/routers/auth.py` |
| 荷物登録フォームの送信エラー表示（画面遷移せずバナー表示） | `app/routers/cases.py`（`/cases/register` のフロントJS） |

- **参照ID**: 未捕捉例外(500)時に `new_ref()`（8桁hex）を発行。`logging.getLogger("errors").exception("[E-SYS-500] ref=... path=...")` で全文＋スタックトレースを出力。Cloud Logging で `ref=xxxx` を検索すれば当該エラーに到達できる。
- **生メッセージ** は必ずログ側に残し、画面/DB/メールにはやさしい説明＋コードのみ（内部情報を露出しない）。

## 3. エラーコード一覧（ERROR_CATALOG）
| コード | ユーザー向け説明 | 管理者向けヒント |
|---|---|---|
| `E-SYS-500` | 予期しないエラーが発生しました。時間をおいて再度お試しください。 | 未捕捉例外。参照IDでログ検索しトレース確認。 |
| `E-VALIDATION` | 入力内容に誤りがあります。赤字の項目を確認してください。（**該当項目名を併記** 🆕） | リクエストのバリデーション失敗（型/必須）。 |
| `E-AUTH-401` | ユーザー名またはパスワードが違います。 | 認証失敗。 |
| `E-AUTH-429` | 試行回数が多すぎます。しばらく待って再度お試しください。 | ログインレート制限に到達。 |
| `E-AUTH-403` | この操作を行う権限がありません。 | 権限不足（管理者専用操作など）。 |
| `E-POST-TIMEOUT` | 投稿サイトの反応が遅く、時間内に完了できませんでした。自動で再試行します。 | Playwright タイムアウト。サイト構造変更/高負荷。 |
| `E-POST-LOGIN` | 投稿サイトへのログインに失敗しました。認証情報をご確認ください。 | Trabox/WebKit ログイン失敗。認証情報の変更/失効。 |
| `E-POST-INPUT` | 投稿内容の一部が投稿サイトに受け付けられませんでした。入力内容をご確認ください。 | サイト側入力エラー（必須/コード不一致。例: vacantarea）。 |
| `E-POST-SELECTOR` | 投稿サイトの画面が変わった可能性があります。管理者にご連絡ください。 | セレクタ不一致。DOM変更の可能性大。 |
| `E-POST-NETWORK` | 通信エラーが発生しました。自動で再試行します。 | ネットワーク/接続エラー。 |
| `E-POST-NOTLISTED` | まだ掲載されていないため、変更・取下げできません。先に投稿してください。 | 掲載番号(baggage_no)が未記録。初回投稿が未掲載/番号取得失敗。**リトライ不可**。 |
| `E-POST-UNKNOWN` | 投稿処理でエラーが発生しました。管理者にご連絡ください。 | 分類不能。error_message 全文を確認。 |

## 4. 自動分類ルール（classify）
投稿系の生メッセージを次の優先順でコードに割り当てる（`app/errors.py::classify`）:
1. `掲載中の番号が見つかりません` / `未登録または削除済み`（＝掲載番号なし） → `E-POST-NOTLISTED`
2. `timeout` / `タイムアウト` → `E-POST-TIMEOUT`
3. `入力エラー` / `invalid` / `受け付け` → `E-POST-INPUT`
4. `ログイン` / `login` / `認証` → `E-POST-LOGIN`
5. `selector` / `locator` / `not found` / `セレクタ` → `E-POST-SELECTOR`
6. `network` / `connection` / `接続` / `econn` / `dns` → `E-POST-NETWORK`
7. それ以外 → `E-POST-UNKNOWN`

## 5. リトライ制御（NON_RETRYABLE_CODES）
- `app/errors.py` に `NON_RETRYABLE_CODES = {"E-POST-NOTLISTED"}` を定義。
- **意味**: リトライしても状況が変わらない（＝Cloud Tasks で再試行しても無駄な）エラー。
- **挙動**: `app/routers/tasks.py` は、全プラットフォームが失敗（`all_error`）かつ、その全てがリトライ不能コードを含む場合、リトライ余地が残っていても**即確定（DLQ退避）**し、無駄な再試行と結果通知メールの連投を止める。
  - 判定: 各プラットフォームの結果 `message`（＝`format_detail` 済みでコード文字列を含む）に、リトライ不能コードのいずれかが含まれるか。
  - 従来の「リトライ上限到達」条件（`retry_count >= _MAX_ATTEMPTS - 1`）との **OR** で `is_final` を決定。
- **背景**: 未掲載（掲載番号なし）の案件を変更・取下げしようとすると「掲載中の番号が見つかりません」で全失敗するが、これは何度リトライしても解消しない。従来は 3 回リトライ＋その都度メール送信が発生していた（2026-07-31 実運用で発覚）。

## 6. E-VALIDATION の該当項目表示（FIELD_LABELS）🆕
- **背景**: 荷物登録フォームで全項目を入力しているのに `E-VALIDATION` になる不具合が発生した際、画面には「入力内容に誤りがあります。赤字の項目を確認してください。」としか出ず、**どの項目が原因か分からず調査に時間がかかった**（2026-08-04）。根本原因は別途 `List[str] = Form(None)` の型宣言バグ（選択数1個の際にリスト化されない FastAPI 0.103系の既知の制約）で修正済みだが、**今後同種の不具合が起きた際に画面から即座に原因箇所が分かるように**、恒久対応として本項目を追加。
- `app/errors.py` に `FIELD_LABELS`（フィールド名 → 日本語ラベルの対応表）を新設。
- `app/main.py` の `_validation_handler`（`RequestValidationError` ハンドラ）が、Pydantic のバリデーションエラー一覧（`exc.errors()`）から失敗したフィールド名を抽出し、`FIELD_LABELS` で日本語化して `detail` に追記する。
  - 表示例: `入力内容に誤りがあります。赤字の項目を確認してください。（該当項目: 必要装備、輸送取扱区分）（コード: E-VALIDATION）`
  - `FIELD_LABELS` に未登録のフィールド名は、フィールド名そのまま（英字）で表示する（隠さない）。
  - 生の Pydantic エラー詳細（型・エラーメッセージ全文）は画面には出さず、`logging.getLogger("errors").warning(...)` でログにのみ残す。

## 7. 荷物登録フォームの送信エラー表示（画面遷移なし）🆕
- **背景**: 従来はフォームの通常の `<form method="post">` 送信のため、サーバーが 4xx/422 を返すと**生のJSONがそのまま表示される画面に遷移**していた（2026-08-04 発覚）。
- `app/routers/cases.py` の `/cases/register` フォームで、送信を `fetch` 化。
  - サーバーが 4xx/422 を返した場合: 画面遷移せず、フォーム上部の赤いバナー（`#register-error`）に `detail` の内容をそのまま表示。
  - 成功時（200 系）: **Post-Redirect-Get（PRG）パターン**でサーバーが 303 リダイレクトを返し、`window.location.href = res.url` で実ページ遷移する。
    - ⚠️ 当初 `document.write()` でレスポンスHTMLを直接差し替える実装をしていたが、CSP nonce 不一致等で不安定に動作し、**登録は成功しているのに画面に何も表示されない**事象が発生。ユーザーが連打し**重複登録**を引き起こした（2026-08-04、group_id 9/10 で発生・実運用で発覚）。PRG方式への変更で解消。
  - 単発登録の成功時: `/cases/{case_id}/manage?registered=1` にリダイレクトし、`registered=1` 時のみ緑色の完了バナーを表示。
  - 複数日程一括登録の成功時: `/cases/group/{group_id}?registered=1` にリダイレクトし、同様に完了バナーを表示。

## 8. どこに出るか
- **フォーム送信のエラー**（ログイン・案件/空車登録・設定保存）: `detail` にコード込みで表示。荷物登録フォームは画面遷移せずバナー表示（#7）。
- **投稿の非同期失敗**: ダッシュボード/案件管理の状態・error_message、結果通知メール、DLQアラートに反映。
- **未捕捉500**: 画面に参照ID付きメッセージ、サーバーログに全文。

## 9. 運用フロー（管理者）
1. ユーザーからコード（と参照ID）を聞く。
2. `E-VALIDATION` は画面に表示される「該当項目」でまず当たりをつけ、必要ならログの `errors=[...]` で型・詳細を確認。
3. `E-POST-NOTLISTED` は「そもそも掲載されていない案件を変更・取下げしようとした」状態。初回投稿の成否（掲載番号の有無）を確認し、必要なら新規投稿し直す。
4. その他 `E-POST-*` は error_message とログの生メッセージで原因を特定。`E-SYS-500` は Cloud Logging で `ref=<参照ID>` を検索しトレース確認。
5. サイト構造変更（`E-POST-SELECTOR`/`TIMEOUT` 多発）ならセレクタ/待機の見直し。

## 10. 監視との連動
- `carroo_error_count`（severity>=ERROR）/ `carroo_dead_letter` / `carroo_login_failure` のログベースメトリクス＋アラートと併用。
- 参照ID・コードはログに残るため、アラート受信後の一次切り分けに使える。
